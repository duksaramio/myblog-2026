## 荷兰政府基于 NixOS 构建微软替代方案
**892 points** · [DAWO](https://www.dawo.community/en/)

DAWO（Digitaal Autonome Werkomgeving Overheid，荷兰政府数字自主工作环境）是内政与王国关系部（BZK）发起的一项倡议，旨在用可替换的组件为荷兰政府雇员构建数字工作空间：包括一个 AI 层、一个基于 NixOS 的操作系统、云基础设施以及协作软件。该仓库基于 flake 构建的 NixOS，拆分为引导（boot）、桌面、环境、硬件、安全加固（hardening）、主机、网络、程序、服务和用户等模块，从而以声明式定义工作环境并实现完全相同的复现。机队管理（Fleet management）由 DAWO-Sextant 提供（作为 Intune 的替代品），并有一个并行的 Fedora Kinoite 轨道作为后备方案。核心仓库此后已从 `code.overheid.nl` 迁移至 Codeberg，“以促进社区协作”，这正是关键所在：荷兰正努力让其工作环境依赖于任何人都能阅读和构建的代码。

官方陈述的理由是依赖性。社区网站列出的自身脆弱性指出：荷兰政府过度依赖非欧洲技术，导致其面临关键外国系统中断、失去对政府数据的控制权、失去管理自身系统的诀窍、间谍活动以及丧失战略自主权的风险。这不是采购层面的抱怨，而是一个威胁模型，并且与欧洲多个部门两年来写下的句子如出一辙：法国有 Securix 和 Bureautix，德国有 openDesk，且没有一个项目是先驱。

讨论帖中指出了两个不容回避的实际问题。首先是办公套件：正如一位评论者所言，如果 LibreOffice 和 Collabora 不能无缝替换 Microsoft 365，该项目就无法落地，而“毫无摩擦”的前提根本站不住脚——帖子中对一次 Excel 文件通过 SharePoint、PDF、权限反复周折的漫长恶搞，并不是在开用户的玩笑，而是一份替代技术栈所缺乏的功能清单。其次是 NixOS 本身：几位评论者将采用它描述为既是福也是祸，DAWO-Sextant 试图解决的机队管理引导问题依然棘手——系统管理员期待的是 Web 控制台，而不是一个 flake。还有评论指出，这些仓库可能会违反 Codeberg 针对 AI 生成代码的新政策，如果一个追求自主权的项目因此受挫，那将是极具讽刺意味的。

## 制作像 Times New Bastard 这样的受诅咒字体
**837 points** · [Bastardica](https://bastardica.mitpit.com)

Bastardica 取一个基础字体和一个混入字体，并以固定步长（每 7 个字形、每 2 个字形，随你选择）替换字形，支持可选的缩放和 Y 轴偏移效果，然后构建出可下载的 TTF、OTF 或 WOFF2 文件。预设包括 Sneaky Bastard（Times New Roman，每 7 个字形替换为缩小至 90% 的 Arial）、Impacter（Impact 字体，每隔一个字形进行拉伸）、Nervous Sans（Arial 叠加五次，抖动错位）、Royal Ransom Note（皇家勒索信体）和 Temu Sans。所有操作均在客户端通过 Pyodide 和 fontTools 运行，没有字体文件离开浏览器。

其真正的工程实现取决于一个决定。它没有要求渲染器提供支持，而是将替换实现为针对每种文字注册的 OpenType `liga` 上下文替换，因此浏览器、设计工具和打印系统都会默认应用它，在整个软件生态看来，该文件就是一个普通字体。叠加三个或更多字体时，步长会开始发生冲突——作者给出的建议是使用质数来降低冲突概率，并坦言排在前面的字体优先。该项目在法律风险上也十分坦诚：将两种字体混合会产生衍生作品，因此商业使用必须核对两者的源许可。

评论区大多充斥着“这是我在凌晨 2 点用 vim 搞出来的”狂欢氛围，这也是对此最合适的回应。唯一一条实质性的评价指出，这是对模因格式（Times New Bastard）的一次重现，但背后有了真正的工具支撑；而将古怪之处参数化为步长的字体，其通用性远超手工捏造的怪异字体。

## 为什么肝脏具有如此不可思议的再生能力？
**537 points** · [dynomight](https://dynomight.substack.com/p/liver)

这篇文章提出的问题是：为什么人体的绝大部分组织都像一次性消耗品——肾脏受损会永久结疤，牙龈萎缩永远无法恢复，耳鸣会伴随终生——而肝脏却能在愈合时不留疤痕，随年龄增长保持接近满负荷的功能，并能在数月内将捐献的一半肝脏重新长全？文章给出的答案颠覆了常识：脆弱其实是一种特性。作者将其阐述为一种在文前就声明是推测性的生物学统一理论：修复能力是在与无限生长这一故障模式（即癌症）之间进行的权衡，大多数组织最终选择了廉价的瘢痕形成，因为这通常足以维持繁殖，而繁殖正是自然选择唯一衡量的指标。

佐证案例是其中最有趣的部分。绝经期在动物界几乎为人类所独有——少数例外包括虎鲸、短肢领航鲸、白鲸、伪虎鲸、一角鲸以及乌干达的一个特定黑猩猩种群。蝾螈能断肢再生；我们则长出疤痕组织敷衍了事。端粒缩短是因为 DNA 聚合酶无法复制到最末端，从而将细胞分裂次数限制在 50 到 70 次。而且器官移植多数最终失败：即便使用免疫抑制剂，大约 30% 的肾脏也会在十年内被排斥。

评论区承担了纠偏工作，应与原文对照阅读而非读完就信。一位在职病理学家推荐将温伯格的《癌症生物学》（The Biology of Cancer）作为严肃探讨的起点。评论者指出，“神经元不分裂”的说法鉴于现有的神经发生文献已经过时；而“免疫系统可能会攻击胰腺”这一句则混淆了 1 型糖尿病与真正与衰老相关的 2 型糖尿病。最强烈的反对意见针对的是文章关于人体为了其他特性而牺牲伤口愈合能力的论点：伤口愈合不良是手术死亡的主要原因之一，因此这种能力绝非可有可无，而是生死攸关的基石。最令人难忘的评论来自一位接受过切除供肝的移植受者，他证实了肝脏的再生——“可能是因为移植方位的缘故”，它朝错误的方向长了过去——这戏剧性地回应了文章自身关于为什么在所有器官中偏偏是肝脏能够再生的调侃。

## 丰田让卡罗拉走向纯电
**420 points** · [Electrek](https://electrek.co/2026/09/23/toyota-best-selling-corolla-electric/)

自 1966 年以来，卡罗拉已售出超过 5700 万辆，历经 12 代更迭；而下一代将是一款纯电车（EV）。丰田约一年前在 Japan Mobility Show 上展示了一款概念车，首席执行官佐藤恒治当时的表述是：“无论是纯电动车、插电混动、混动还是内燃机汽车——无论动力来源是什么——我们都要造出人人都想驾驶的漂亮汽车。”预计该平台将是经过深度改造的 TNGA-C 架构，支持所有动力总成，而非纯粹的纯电专用平台。丰田章男在 7 月对 NHK 表示，在中国同行的竞争压力下，公司被迫做出改变，“否则将无法生存”。

请再读一遍那位 CEO 的原话，因为这正是问题的核心所在。“无论动力来源是什么”是一种对冲策略，而一个被设计为兼容所有动力总成的平台，与打造优秀电动汽车的要求背道而驰——评论者指出了雷克萨斯 ES350e，该车共用混动/纯电平台，被广泛批评为平庸的纯电动车，相比之下，从一开始就作为纯电动车设计的 bZ 和 bZ Woodland 则被认为表现合格。二十年来，丰田一直是阻挠电动化最顽固的汽车制造商之一，而作为专门报道电动车的媒体 Electrek，对这段游说历史竟然只字未提。一条热评写道：“在终于妥协之前，他们付出的代价仅仅是二十年的时间以及数百万美元的反电动车游说支出，对吧。”

需求端是这篇报道变得耐人寻味的地方。讨论帖中卡罗拉潜在买家表达的真实偏好既非纯电也非混动——他们想要的是一台装有电驱动力总成、DIN 规格插槽和 Android Auto 的 1995 年款 Starlet，这本质上是对一台廉价机械家电的呼唤。丰田受限的产品线表明它甚至无法提供这样的产品：在希腊，只有混动版 Yaris 和 Yaris Cross 可买，没有汽油版，没有柴油版。而市场对纯电动车为何遇冷给出的答案是：想买的人早就买过了，这正是主流车企纷纷削减项目而非推出新车的原因。电动卡罗拉是一次货真价实的转向，但它更像是一辆在共享平台上诞生的合规积分车，而非丰田真心笃定的产品。

## Rails World 2026 开幕主题演讲
**416 points** · [YouTube](https://www.youtube.com/watch?v=vDjW_dRyKXY)

DHH 在奥斯汀的 Rails World 开幕式上宣布：“我已经从专业程序员的身份退休”，转而自称为创造者（maker）。演讲的核心内容包括：手写代码对“绝大多数公司的绝大多数程序员而言，已不再是一项具有经济效益的工作”；英语是他用过的最好的编程语言；人类并不一定需要去阅读大模型产出的代码——那应该是例外，“就像在 Sentry 中查看 bug 一样”。到今年年底，“几乎所有领域、几乎所有程序员、几乎所有公司”。37signals 已经停笔不再手写代码，正在将 HEY 重构为覆盖所有平台的原生应用，其后端为智能体编写的 Rust。他依然坚称 Rust 丑陋至极、不该让人类去忍受，但对大模型而言非常合适——既然他不读代码，也就能欣然享受其性能。新版 HEY 的服务器数量预计将从 110 台骤降至接近 10 台；他声称峰值流量完全可以在树莓派上运行。演讲在拒绝 AI 怀疑论的呼吁中收尾：“消极悲观（black pill）是彻头彻尾的懦夫行为。”

这次演讲更适合被解读为一种偏好的表露，而非严肃的预测。Rails 延续了二十年的招牌主张——约定优于配置、小团队、雄心勃勃的产品——在这里被重新包装为“Token 效率”，而 Evil Martians 的智能体评估报告被用来安抚大家：AI 已经非常擅长写 Rails 了。然而，在世界顶级 Rails 大会的开幕演讲上，他却宣布一款旗舰级 Rails 应用正在抛弃 Rails；关于该框架的评价最终缩水为“对像 Basecamp 这样的 Web 应用仍然适用”。前排一位评论者精准地形容现场气氛是“我经历过的最令人困惑的葬礼”。

值得记住的技术反驳来自工程实质。Rust 重写的成功几乎与是否拥有优秀的测试套件成线性正比，而未解之谜在于测试套件协助重写完成之后会发生什么：新功能如何在全新后端上构建，代码质量能否保持。前一天，一位从事 GPU 内核开发的评论者在另一个语境下也对智能体提出了同样的观点——可衡量的目标加上写权限，产生的只是针对特定指标的优化。而在 DHH 立场之下的设计疑问在于：如果每个应用最终都只是智能体的 CLI，那么固执己见的 UI（opinionated UI）其价值就变成了零，这对于一家所有差异化都建立在独特 UI 理念上的公司来说，是一个奇怪的归宿。他在同一场宣称所有人都想要 CLI 的演讲中，却因为 Web 体验不够精致而把 HEY 用六个原生客户端重写了一遍。

## Opus 5.5 擅长制作解说视频
**393 points** · [launchvideo.io](https://launchvideo.io)

给它一个 URL 或一段提示词，就能直接生成 MP4 视频，且整个流程完全没有调用任何视频模型。该管线是部署在 OpenComputer 上的无服务器智能体：一个智能体文件、三个工具，每个任务启动一个全新的微型虚拟机（Amazon Linux 2023 arm64，4 vCPU，8 GB 内存，Node 22），通过网关调用 `anthropic/claude-opus-5.5` 模型，每条视频大约消耗 9 万输入 Token 和 1.5 万输出 Token，其中绝大多数内容是智能体手写的 HTML 和 CSS 转场标记。`web_fetch` 返回网页文本、标题、各级标题、最高频使用的十六进制色值及 Google Fonts。`check_scene` 加载视频画面，并报告采样时间戳上的 JS 错误和可见文本。`render_video` 负责渲染并上传。

值得借鉴的核心技术是渲染循环。它没有采用录屏手段。页面的所有时钟机制——`requestAnimationFrame`、定时器、`Date`、CSS 动画、Web Animations——都被替换成了虚拟时钟，因此每一帧画面都是确定性的 seek 操作，而非与真实墙钟时间（wall time）竞速。分辨率为 1920×1080、30fps，JPEG 帧以 crf 18 的质量直通 libx264。这正是输出结果完全可复现的原因，也是整个流程能够塞进一个仅需在首次工具调用时安装静态 ffmpeg 二进制文件和无头 Chromium 的微型虚拟机的原因。存储设计也相当干净：智能体不保存任何密钥凭据；表单生成一个限定在单一路径且有效期为三小时的 Vercel Blob 上传令牌，工具通过任务 ID 即可拉取。

讨论帖中的异议十分公允，且并未贬低其技术本身。评论者指出，HTML 配合 Playwright 再加上 ffmpeg 的方案早于 Opus 5.5 数年，并不是什么模型专属能力；此外，如果不事先了解主题，画面切换太快根本来不及阅读；而在演示的 Jev 视频中，整整 30 秒都在重复“Jev 由 TypeSafe AI 打造，Jev 更快更便宜”，这是直接抓取着陆页导致的必然结果。热评对这类形式本身的批评比对工具更为严厉：解说视频是一种用以替代文字教程以投放广告的不良设计模式（dark patterns）。这些批评都切中要害。但同样成立的是：确定性时钟是让视频生成变得具有可测试性的关键所在，无论这些 HTML 究竟由谁编写，这一理念都极具迁移价值。

## Whiteboard — 专为深思熟虑的软件设计而打造的开源 IDE
**385 points** · [GitHub](https://github.com/devdotfast/whiteboard)

/dev/fast（YC W26）推出了一款桌面应用程序，让开发者和智能体能够在同一个工作空间中完成软件架构设计。它基于 CodeOSS 构建，这是一个关键的基础性决定：点击时序图、ER 图或智能体执行轨迹中的某句话，就能直接跳转到对应的底层代码，原生继承了 VSCode 的快捷键和 LSP 支持。智能体获得了在画布上绘图的 SDK，并且内置了一个决策日志，智能体可以查询该日志并关联自己的执行轨迹，让你可以直观看到哪些决策是它自主做出的。他们还用 Rust 编写了一个具备语义和 AST 感知的 diff 查看器：大型新增函数会被精简提炼为伪代码，单元测试和大幅文档修改默认折叠，并且 WASM 插件系统允许用户自定义这些规则。采用 MIT 许可证，支持 macOS 和 Linux（提供 Fedora 构建版本），完全支持自托管。

名称是该项目最薄弱的环节，他们在讨论帖中也半推半就地承认了这一点——之所以选择“IDE”，是因为人们现在习惯在 VSCode 中做代码评审。它在设计上刻意不提供文件编辑功能；他们的理由是，编辑功能会把产品拖向成为调度器或超集工具的泥潭，而他们更希望主导代码理解层。这一论据站得住脚，多位整天评审智能体输出的评论者也表示，语义 diff 正是他们一直渴求的功能。

有两点值得关注。一位用户报告称 Codex 会发出警告：“Whiteboard 要求将仓库数据上传/公开到其创作服务器”——这与“目前仅限本地运行”的宣传不符，正是用户将其用于私有仓库前必须彻底查清的问题。此外，一位评论者指出示例图表中的一个状态流转标签在对应的 diff 中根本找不到支撑，这也是 LLM 绘制图表的普遍风险：无论是否属实，图片看起来总是显得权威可信。团队的付费模式是一个托管的 Web 版本，提供执行轨迹存储和多人协作评审；核心部分仍保持完全自托管。

## 2DWillNeverDie
**318 points** · [2dwillneverdie.com](https://2dwillneverdie.com/)

一个像素艺术档案库——汇集了来自《拳皇》（King of Fighters）、《漫威对卡普空》（Marvel vs Capcom）、《怒之铁拳》（Streets of Rage）、《洛克人》（Mega Man）、《银鹰骑士》（Silverhawks）、《装甲勇士》（Cyberbots）等作品的像素画廊及教程——包裹在一个运作机制如同游戏本身的网站中，处处暗藏彩蛋（输入科乐美秘技会有惊喜反应）和交互小细节。互联网档案馆记录该网站大约始建于 2010 年，这也印证了当前版本是纯手工打造而非机器生成的痕迹。

讨论帖争论了为什么 2D 能够经受住时间的考验，而早期 3D 却无法做到，并得出了一个站得住脚的结论：手绘像素之所以在低分辨率下仍具辨识度，是因为艺术家精心挑选了需要表达的细节；而第一代 3D 只有在高保真度下才具有辨识度，当年的硬件根本无法承载。这种怀旧并不仅仅是情绪作祟。卡普空的像素制作工艺反复被誉为“失落的技术”——其格斗游戏和《龙战士》（Breath of Fire）系列的流畅度，至今仍未被延续该格式的独立游戏圈完全超越。

落到实用层面：像素动画是成本最高的部分，几位评论者描述了现代的工作流程：先构建并绑定 3D 角色骨骼，然后将其渲染烘焙成像素动作序列帧（sprite sheet），有时还会将纯 2D 像素混合到 3D 场景中做成 2.5D。面对真实的成本痛点，这是货真价实的工程解法，与人们通常在此类链接中看到的复古情结大相径庭。

## Fearless SIMD v1.0
**307 points** · [linebender.org](https://linebender.org/blog/fearless-simd-1-0/)

在最初原型问世八年之后，`fearless_simd` 迎来了 1.0 版本，彻底将 `unsafe` 移出了 Rust 中的手写 SIMD。该设计满足了三个层面的诉求：普通的自动向量化与多版本支持（multiversioning）、完整的可移植 SIMD 抽象，以及在需要特定指令时安全访问平台内建函数（platform intrinsics）。当不同平台在边界情况表现不一致时（如动态重排 swizzle、浮点最大值），该库同时提供了在所有平台上表现完全相同的精确变体，以及直接返回硬件原生结果的快速变体，并允许你根据原生向量宽度表达算法，或在算法有严格要求时固定宽度。为了让可移植实现的性能保持竞争力，团队投入了大量精力，相关改进还反哺贡献给了 Rust 和 LLVM 上游。

最有力的证明来自采纳它的项目。FFT 库 PhastFT 放弃了仅限 nightly 的 `std::simd` 和 `multiversion`，现在完全基于 `fearless_simd` 运行在 Rust stable 上。基于它构建的多字节集合搜索工具 `memchr-n`，在基准测试中的速度甚至超过了标准 `memchr` 库（即便是在 `memchr` 原生支持的 1 到 3 字节集合上）。这正是让 SIMD 抽象值得采纳的标准范例：它移除了对 nightly 工具链的依赖，且凭借实测数据而非理念口号胜出。

讨论帖提出的未决问题非常切中要害。这与多年来一直支持便捷动态派发的 ISPC 相比如何？与 Google 的 Highway 相比又如何？Go 语言的努力即将从另一个方向回答这个问题——参见下一节。另一个引发讨论的愿望是编译器辅助的特化：这是 LLM 时代版本的“编译器判断出哪一部分双精度浮点数不可能为 NaN，从而选择更快的 min/max 指令”，目前还没有任何语言能很好地实现这一点。

## Go 语言中的平台无关 SIMD
**299 points** · [Go Blog](https://go.dev/blog/simd-experiment)

Go 1.26 为 amd64 添加了 SIMD API，1.27 将其扩展到 arm64 NEON 和 wasm，放在与架构强相关的 `archsimd` 包中，因为不同硬件的向量宽度和支持的操作差异巨大。1.27 中真正值得关注的改动是一个独立的、完全可移植的 `simd` 包，大致参考了 C++ 的 Highway：一次编写，在存在 SIMD 的平台上获得接近汇编的性能，在不支持的平台上获得合格的模拟实现，目前支持 AVX/AVX2/AVX-512、NEON 和 wasm SIMD 作为后端。它从类型系统中隐藏了固定大小向量，支持跨平台操作的交集，并通过其他 SIMD 指令进行模拟来补足差异。甚至 Green Tea 垃圾回收器都在使用 SIMD 扫描内存中的存活对象——这不再是冷门的小众技术。

讨论帖提供了官方公告中缺失的基准测量：在一个 wasm 调色板替换基准测试中，可移植 SIMD 比非可移植 API 慢约 11%，但两者都比标量代码快大约 5 倍。这就是一句话能说清的权衡：用极小的常数开销，换取免去针对每个架构编写内建函数大杂烩的代码。有评论者在设置了 `CGO_ENABLED=0` 的语音转文字和文字转语音项目中使用了该包，报告了相较于纯 Go 的可衡量提升；还有人指出，这是他们见过的第一个可移植抽象，让可变宽度的 SVE 和 RISC-V 向量寄存器变得易于驾驭，而不再是特殊个案。

两点注意事项。这目前属于实验性质，在 Go 的语境下意味着 API 可能会发生变化，且当前实现包含一个由编译器特化消除的类型 switch——一位评论者合理地质疑，在可能运行于未知硬件的二进制文件中这何以实现，在基于它构建之前很值得一读其中的解答。此外，今天的另一篇 SIMD 报道也是一个提醒：“可移植与安全”只有在数据支撑得住时才有意义；两种语言在同一周从完全相反的起点达到了同一点，但谁都没有随公告附带自己的权威基准测试。

这一领域早已有了一座公墓，讨论帖对此心知肚明：Fossil SCM、git-appraise、Epiq、gitseq 以及十年间因相同原因走向消亡的众多“分布式缺陷跟踪器”——缺乏权限模型、缺乏跨仓库视图，以及集成摩擦。git-bug 自身的 issue 追踪列表展现了后续工作的艰难轮廓；一位评论者指出了一个涉及 ssh-agent 的已知阻碍性问题需要规避，而身份管理正是作者转而调研 Bluesky 密钥分发而非自己手写加密算法的原因。

客观的定性是：与代码放在一起的 bug 追踪适合小团队和单一代码库，而大多数团队之所以不采用，原因在于社交而非技术——issue 追踪器是其他人员（客服、产品、外部上报者）被允许提交内容的地方，而这部分受众并没有代码库权限。这恰恰是路线图中 Web UI 和外部认证所针对的目标人群。这里的一切都是在打赌“缺陷跟踪器是一个独立的 SaaS 产品”这一既定现状并非不可逆转，而如今由于智能体拥有本地 Git 访问权限，这种逆转的可能性正变得越来越高。

## 在 M6 Mac Mini 上的 86Box 模拟器中运行 600MHz Pentium II 与 Voodoo 3

对于年龄比这套硬件还小的读者来说，讨论帖中的怀旧情绪并不是因为当年的游戏画质更好，而在于从纯软件渲染迈向硬件加速，是同一年硬件升级最后一次带来肉眼可见、不容置疑的颠覆性飞跃——好几个人指出，最早一批 3D 游戏看起来其实比它们所取代的 2D 游戏要粗糙得多。唤起这股情怀的基准测试遗迹是 3DMark 2000 和一只特定的鬣蜥。

## 贯穿线索

**核心主题是退出成本（exit cost），今天它呈现在通常不会放在一起讨论的四个机构案例中。** 荷兰政府正基于 NixOS 和 Fedora Kinoite 重建其工作环境，因为他们无法从外国供应商的路线图中脱身——而讨论帖立即指出了真正决定成败的绊脚石，并非操作系统本身，而是 LibreOffice 能否平稳承接离不开 Excel 和 SharePoint 的庞大用户群体。哥伦比亚特区巡回法院维持了五角大楼将 Anthropic 列入黑名单的决定，这是从另一面解读的同一关系：一家供应商试图保留对其产品使用方式的控制权，因而被直接从供应链中剔除。DHH 利用 Rails 主题演讲宣布 HEY 正在抛弃 Rails，而真正有价值的分析——即 Rails 一直以来都只是权宜之计，“约定优于配置”已被悄然重新定义为 Token 效率——出自社区成员，而非这位创始人。诺基亚的档案馆则是这一幕的善后景象：二十年的设计决策，在一辆货车中用 24 小时抢救出来，如今因为无人售卖而仅获准用于学术研究。而在最小的层面上，F-Droid 一夜之间暴涨 814 分源自同一种本能——世界某处的某些人，渴望一个不会因为平台的一道指令就被掐断的应用商店。所有这些案例，都是有人在为此前被视作免费的依赖性重新定价。

**其次：今天最出色的工程实践关乎确定性（determinism），而最糟糕的观点恰恰相反。** 解说视频管线之所以令人惊叹，不是因为模型编写了 HTML，而是因为它将浏览器的时钟替换为虚拟时钟，使得每一帧都成为一次确定性的 seek——没有录屏，输出完全可复现，且可被测试。Fearless SIMD 和 Go 的可移植 `simd` 都是试图在性能工程中消除不确定性的努力：前者将 `unsafe` 和 nightly 工具链从 Rust SIMD 中剔除，后者将按架构划分的内建函数大杂烩从 Go 中消除，两者都是凭借测量而非许诺走到今天——社区的 wasm 基准测试表明可移植 SIMD 仅比非可移植 API 慢 11%，且比标量快 5 倍，这是一个你可以付诸实践的硬指标。86Box 是将确定性做成了产品：它在底层将 1990 年代的 PC 精确模拟到芯片组和总线时序，使得当年的软件能够正常运行，其带来的实际结果是该设备的单核性能纪律远比多核数量重要得多。与所有这一切形成鲜明对比的，是 DHH 对着一群维护系统的受众所讲的“我们甚至不需要阅读代码”，而他在同一场演讲中却因为 Web 体验不够精致而把一个应用重写为六个原生客户端。今天的演讲中唯一真正具有可迁移性的工程逻辑是他未曾明言的那句话：如果你无法将其量化为一个整数，你就无法真正信任它；如果你不打算去读它，你最好去严密地度量它。

**第三：今天的首页将目光投向了 AI 的供给端，而受众奖励了那些不起眼的脏活累活。** Google 正在测试其芯片在辐射和真空环境中能否存活，并坦诚列出散热是一项挑战，承认一切未有定论。一家开发工具初创公司推出了语义 diff 查看器和决策日志，因为评审智能体的代码输出如今已成为效率瓶颈。一家微控制器厂商发布了明确标明非用于生产的 Linux BSP，而社区已经在为其移植内核，并在评论区激烈争论主线移除 RISC-V 就地执行是否是个错误。一家游戏工作室将其轴测美术重新设计为可打印几何体并免费开源了文件。一个不懂 JavaScript 的人做出了一个游鱼池塘。与此同时，本周早些时候发布的几个大模型仅仅上涨了 7 分、9 分和 5 分，而一项关于采购的法庭裁决得分超过了所有这些模型。数字背后的真相是：能力本身已经不再稀缺；真正稀缺的是基础设施的修补打磨、严格的验证机制，以及随时抽身离开的底气。
