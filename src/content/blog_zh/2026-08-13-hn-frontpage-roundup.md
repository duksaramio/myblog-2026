## DeepSeek Harness 开发者预览版 — 473 点

[源链接](https://deepseek.com/harness/en/)

DeepSeek 正在为代理基础设施层推出“Harness”，这是一个开源框架，其中每个功能——模型、工具、技能、会话、沙箱、存储、调度，甚至用户界面——都可以作为可互换的插件。它基于 Cordis，这是一个插件系统，用于管理组件的挂载、卸载及其之间的依赖关系。其口号是“代理 = 模型 + Harness”，这表明单独的模型是不够的。

框架提供了四种运行时模式：标准模式（全面编码代理）、代码模式（通过 TypeScript 实现多步骤工具编排）、最小模式（命令行 + 文件编辑器用于基准测试）和创作者模式（运行时检查和插件实验）。有一个只读的会话日志，记录了模型所看到的一切——系统提示、推理、工具调用、子代理调度——使运行完全可追踪和可重放。

“一切都是插件”的宣传听起来在架构上很干净，但真正的考验是插件生态系统是否真正实现。DeepSeek 正以 MIT 许可证发布此开发者预览版，这是采用的正确步骤。有趣的是，DeepSeek 想同时成为模型提供商和框架层——社区是否会围绕他们的框架构建，还是自己开发，还有待观察。

## Codex 在 ChatGPT 桌面应用（Linux 版）中 — 417 点

[源链接](https://community.openai.com/t/codex-in-chatgpt-desktop-app-for-linux-is-now-in-preview/1390027)

OpenAI 的 ChatGPT 桌面应用与 Codex 集成现在在 Linux 上提供预览版。支持的发行版包括 Ubuntu 24.04/26.04 LTS、Debian 13 和 Fedora 43/44，提供 x64 和 ARM64 的 .deb 和 .rpm 包。公告线程已有 13600 多次浏览和显著的社区参与。

该应用将 ChatGPT、工作和 Codex 整合到一个原生桌面体验中，用于管理项目、处理文件以及在 Codex 旁边运行浏览器工作流。这是 Linux 用户首次在浏览器之外获得一流的 Codex 体验，社区反应如预期般热烈——对于 OpenAI 下载页面上不一致地隐藏 Linux 选项，用户提出了常见的抱怨。

真正的故事是 OpenAI 终于将 Linux 作为其开发工具的头等公民对待。大多数严肃的开发都在 Linux 上进行，而之前的 Mac/Windows 专用桌面应用是一个明显的空白。Electron 包装是否值得与网页应用相比，仍然是一个开放的问题，但原生文件系统访问和更紧密的 Codex 集成可能会带来差异。

## DRAM 蜘蛛化 — 362 点

[源链接](https://github.com/xoreaxeaxeax/skitter-creek-bath-salts)

这是一项硬件安全研究，让你质疑你所知道的一切关于内存隔离的知识。该项目“skitter-creek-bath-salts”由 xoreaxeaxeax 完成（该研究员还负责原始 MOVfusculator 工作），展示了如何通过操纵 DRAM 控制器的地址转换层来解锁 AMD CPU 上的一切——一个简单的 `xor dword` 指令，翻转内存控制器中的一个位。

核心洞察极其简单：平台上的所有安全机制——平台安全处理器 (PSP)、系统管理模式 (SMM)、C6 空闲状态 DRAM 分区、甚至 CPU 微代码——都位于地址转换管道中的内存控制器之上。锁保护的是物理地址，而不是实际的 DRAM 坐标。重新排列坐标，障碍就永远不会注意到。

该项目详细介绍了提取 PSP 的 RSA 引擎（fTPM 的模指数运算），从 SMRAM 读取 SMM 入口向量，从 C6 分区中提取 CPU 寄存器状态，甚至从 DRAM 中拉取实时微代码补丁——所有这些都通过相同的别名访问技术。它使用 z3 来解决从普通视图到“蜘蛛化”视图的 GF(2) 线性映射。该项目在 AMD Family 16h 上开发（最后一个记录了 DRAM 控制器寄存器的文档化一代），但底层转换扩展到 ARM 和 RISC-V。整个漏洞利用仅需一个 XOR 指令。该研究采用 MIT 许可证。

## Gemini 3.7 Flash — 353 点

[源链接](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-3-7-flash/)

Google 在推出 Gemini 3.7 Flash 仅三周后就推出了这款产品，并将其定位为“迄今为止最智能的工作马车模型，适用于编码和代理。”基准测试声称：FrontierCode 1.1 Main 从 34.4% 提升到 43.6%，DeepSWE v1.1 从 49.0% 提升到 65.3%，WebDev Arena Elo 从 1538 提升到 1588。对于知识工作，它声称在 GDP.pdf 上获得 34.0%（与 22.0% 相比）和在 AutomationBench 上获得 30.4%（与 17.0% 相比）。

定价具有竞争力——通过年底，输入令牌每百万 0.75 美元，输出令牌每百万 3.75 美元，作为入门价格，这比原始 3.6 Flash 的价格减半。Google 显然希望将 Flash 作为生产代理部署中的默认选择，特别是在成本方面。

“三周的发布周期”可能是真正的算法突破，也可能是营销冲刺。基准测试的改进在纸面上是显着的，但正如往常一样，供应商选择的基准测试应谨慎对待。真正的考验是生产用户是否在实际工作中看到这些收益，而不仅仅是经过精心策划的评估。Google 还将此与 Gemini Spark 结合，这是他们的“24/7 个人代理”，这表明该模型正在被优化以进行持续的自主操作，而不是一次性查询。

## Gloomberb — 321 点

[源链接](https://gloom.sh/)

Gloomberb 是一个开源的 Bloomberg 终端替代品——一个基于键盘的金融终端，既可用作桌面应用，也可用作 TUI。它涵盖了报价、图表、财务数据、SEC 报告、机构持股数据（13F）、期权监控、预测市场（Polymarket/Kalshi）、收益率曲线、外汇、宏观经济事件以及甚至国会交易披露。命令栏界面使用如 `DES`（证券详情）、`TOP`（排名故事）、`PM`（预测市场）和 `CG`（国会交易）等简短代码。

该项目在 GitHub 上有 1200 个星标，版本为 0.10.4。通过 `curl -fsSL gloomberb.com/install | bash` 安装，这取决于你的威胁模型是方便还是一个红旗。其功能集对于免费工具来说确实令人印象深刻——它涵盖了零售投资者或独立分析师所需的大约所有内容，而无需每年 24000 美元的 Bloomberg 订阅。

真正的问题是数据质量和延迟。Bloomberg 的价值不仅在于终端——还有数据基础设施、Bloomberg Chat 的网络效应以及机构级的馈送。Gloomberb 从公共来源获取数据，这意味着它在用户体验和可访问性方面竞争，而不是数据独占性。对于独立研究人员、小型基金以及不需要机构合规功能的人来说，这可能已经足够了。

## 通过线

今天的首页主要围绕两个主题：AI 代理基础设施军备竞赛和硬件安全假设的持续解构。

DeepSeek、Google 和 OpenAI 都在同时对代理堆栈进行动作——DeepSeek 通过开源框架“Harness”，Google 通过成本优化模型针对代理工作流，OpenAI 则终于将他们的开发工具带入 Linux。他们的定位不同，但赌注相同：能够真正自主工作的代理将是下一个战场。DeepSeek 在押注于可组合性，Google 在押注于价格性能，而 OpenAI 在押注于开发者生态系统锁定。

与此同时，DRAM 蜘蛛化研究提醒我们，硬件安全往往只是表面文章。一个简单的 XOR 指令就能绕过平台提供的所有内存保护——PSP、SMM、fTPM、微代码——这种发现应该让安全架构师彻夜难眠。这也是一项美丽的工程，展示了当你攻击基础而不是构建在其上的抽象时，安全模型是如何失效的。

Gloomberb 作为实用的反衬——并非一切都是关于 AI 代理和硬件漏洞。有时你只是想在不支付六位数费用的情况下查看股票图表。
