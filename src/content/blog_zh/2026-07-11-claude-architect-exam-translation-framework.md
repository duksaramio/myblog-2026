这一周我花了大量时间准备Claude认证架构师考试。每本备考指南都告诉你首先要掌握的是“将业务问题转化为基于Claude的AI解决方案”。我以为这会是一个清晰、定义明确的能力。实际上并非如此。阅读了十本备考指南加上官方考试指南后，我发现关于考试名称的描述一半是神话，一半是cargo cult，真正的转换技能隐藏在七个官方任务陈述中，而这些任务陈述在指南中提及甚少。

这是我的发现和值得学习的内容。

## 考试名称不是“专业版”

大多数备考资料都称其为“Anthropic认证架构师——专业版”考试，并且将Domain 1的权重标为17%。这些都是错误的。

真正的考试是**Claude认证架构师——基础（CCA-F）**，于2026年3月13日作为Anthropic合作伙伴网络的一部分推出。考试共有60个问题，评分范围为100至1000分，通过分数线为720分。Domain 1是“代理架构与编排”，占**27%的分数**，而不是17%。Domain 1也不是“解决方案设计与架构”。

这很重要，因为如果你备考的领域名称有误，你的备考重点就会失衡。考试更重视代理架构与编排，而不是通用解决方案设计。转换技能是其中的一部分，但它是底层，不是重点。

## “将业务问题转化为Claude解决方案”不是官方任务陈述

这里有一个让我最惊讶的部分。我一字一句地阅读了官方PDF。没有以“将业务问题转化为基于Claude的AI解决方案”为题的官方任务陈述。无论是在Domain 1还是其他地方都没有。

最接近的是Domain 1中的七个官方任务陈述：

1.1 设计并实现自主任务执行的代理循环
1.2 使用协调者-代理模式编排多代理系统
1.3 配置子代理调用、上下文传递和启动
1.4 实现多步骤工作流，包括执行和移交模式
1.5 应用代理SDK钩子以拦截工具调用和数据规范化
1.6 设计复杂工作流的任务分解策略
1.7 管理会话状态、恢复和分支

转换技能是让你能够正确回答这七个任务的关键。每个官方情景都始于一个业务背景（如客户服务代理、多代理研究系统、结构化数据提取），你需要将这些映射到正确的架构上。但评分标准在于你是否选择了正确的架构形状，而不是你是否优雅地阐述了业务问题。

这种区别将“阅读了十本指南”与“通过了考试”区分开来。

## 真正起作用的转换框架

这里是我实际会用来备考的5步框架，它是通过对比用户指南和Anthropic的“构建有效代理”工程博客而提炼出来的。

### 第一步——发现并拆解

在接触架构之前，先找到实际的痛点。问：

- 谁有痛点？（行动者——高管、操作员、客户？）
- 他们试图完成什么，而不是他们要求的工具是什么？（要完成的任务）
- 今天是如何完成的？（基线——成本、时间、错误率）
- 有哪些约束？（监管、延迟、成本上限、需要人机共存）
- 成功的标准是什么，用一个数字表示？（成功指标）

每本备考指南都强调这一点。每个考试情景都会测试你是否做到了这一点。

### 第二步——决定这是否是一个Claude问题

应用Claude适用性测试：

1. 输入或输出是否是非结构化的自然语言？如果不是，使用传统代码。
2. 是否需要模糊性、判断或综合？如果不是，使用规则。
3. 是否需要超出查找的世界知识或推理？如果是，Claude是强候选者。
4. 失败是否可以通过人机共存或护栏来限制？如果不是，不要完全自动化。

许多备考指南中的实践情景被描述为“必须使用Claude”时，其实使用确定性代码会更好。考试会因为你过度AI化工资税计算而惩罚你。

### 第三步——分类问题形状

从官方情景中，五个反复出现的形状映射到默认模式：

| 形状 | 默认模式 |
|---|---|
| 分类/提取 | 增强型LLM，带有结构化输出 |
| 生成/综合 | 工作流（检索→生成→验证） |
| 推理/决策 | 带有分解或代理循环的工作流 |
| 对话/编排 | 带有显式工具和升级的代理 |
| 发现/搜索 | RAG或多代理研究系统 |

你看到的每本指南中的“增强型LLM/工作流/代理”三分法实际上是错误的。Anthropic的官方层级将增强型LLM视为**构建块**，工作流和代理是两个更高层次的形状。工作流有五个命名子模式：提示链式、路由、并行化、协调者-工作者和评估者-优化器。用户指南中没有提到这五个命名模式。这是一个缺口。

### 第四步——选择架构形状并应用Domain 1技能

选择工作流或代理：

- **工作流**适用于已知输入和可预测的步骤。合规性、审计和可预测的业务流程。
- **代理**适用于开放性问题，你无法预测步骤的数量。

升级规则（来自Anthropic的博客）：从简单开始，只有在更简单的选项明显失败时才升级。大多数生产系统应该是工作流，而不是代理。

然后，无论你选择哪种形状，考试中出现的官方Domain 1技能是：

- **`stop_reason`字段**用于循环控制。继续使用`tool_use`，终止使用`end_turn`。永远不要根据自然语言来决定何时停止。永远不要使用迭代上限作为主要控制流。永远不要检查`response.content[0].type == "text"`作为完成指示（文本和工具使用块可以在同一响应中共存）。
- **中心辐射式编排**，子代理不继承协调者的对话历史。
- **`Task`工具**用于启动子代理。`allowedTools`必须包含"Task"，以便协调者可以调用子代理。
- **程序化执行**用于关键的合规步骤。考试中最常测试的概念：当业务规则是“在退款前验证客户身份”时，使用程序化闸门，而不是提示指令。
- **`PostToolUse`钩子**用于结果规范化和预调用钩子用于策略执行。
- **任务分解**适用于工作流。提示链式用于可预测的多方面审查。动态分解用于开放性调查。

### 第五步——映射到价值支柱并以业务价值为框架

每个考试答案都需要将业务价值闭环。指南中反复提到的五个支柱是：效率、转型、生产力、成本、性能SLA。

但这里有一个我想指出的事情。**Anthropic自己的文档中从未使用过“价值支柱”这个词**。它可能是一个有用的备考术语。它可能是一个第三方cargo cult。无论哪种方式，考试都会奖励你将架构与可量化的业务成果联系起来。

指南正确识别的陷阱是：“减少30%的客服处理时间”听起来像是生产力，但实际上是效率。 “让客服代理处理2倍的工单而不烧脑”是生产力。措辞很重要，因为效率和生产力会驱动不同的架构选择。

## 导致备考指南出错的医疗账单问题

一个指南提出了这个实践问题：

> 一家医疗账单公司分析一份150页的病人记录（约60K个标记）和一份5页的保险政策文档（约2K个标记）。他们每天为2000名不同的病人处理相同的政策。他们应该如何处理政策文档？

选项A：RAG流水线来分块和检索。
选项B：将政策文档附加到系统提示的末尾，使用提示缓存，将病人记录作为用户消息传递。
选项C：将政策文档放在开头并加上`[co-locate]`标签，启用提示缓存，流式传输病人记录。

指南没有给出答案。让我来给出答案。

**A是错误的**。RAG适用于大型、动态或无限的语料库。一个2K标记的政策文档，可以完全包含在上下文中，并且在每次请求中都相同，是使用提示缓存的教科书案例，而不是RAG。

**B大部分正确，但有一个微妙的错误**。如果你在用户消息中包含的可变部分上放置`cache_control`，每次请求的前缀哈希都会不同——没有缓存命中。断点应该放在**静态系统前缀的最后一个块**上，而不是可变块上。Anthropic的文档称其为“常见错误”。

**C是错误的**。`[co-locate]`不是Claude的功能。它是从另一个平台幻想或引入的。提示缓存通过前缀匹配已经实现了内容共存；没有特殊的标签存在。

正确的版本：将政策文档放在系统提示的开头或结尾，标记政策文档的最后一个块为`cache_control: { type: "ephemeral" }`，并将病人记录放在用户消息中。每天有2000个相同的政策请求，你只需在第一次写入缓存，其余请求的输入成本为0.1倍基础输入。这在政策部分上减少了90%的成本。但更重要的是——**实际考试中不会出现提示缓存实现细节**。官方PDF列出了“提示缓存实现细节（超出知道其存在）”为不会出现的话题。因此，实践问题有助于建立直觉，但不代表CCA-F。

## 需要记住的反模式

考试喜欢测试六个特定的反模式：

1. **解析自然语言以确定循环终止**。使用`stop_reason`。
2. **任意迭代上限作为主要停止机制**。上限是安全网，不是控制流。
3. **检查助手文本内容作为完成指示**。文本和工具使用可以共存。
4. **仅通过提示进行确定性合规性执行**。使用钩子/闸门进行财务、身份、退款等。
5. **工具描述重叠**。18个工具带有少量描述会降低选择性。重命名、拆分、差异化。
6. **一次性审查大输入**。注意力分散会导致矛盾的发现。拆分成逐项审查和整合审查。

## 我接下来要复习的内容

转换技能是真实且有用的。它是几乎所有考试问题的基础。但备考的方法不是记忆一个五步转换框架。而是要记住七个Domain 1任务陈述和每个任务陈述中的技能列表。然后，转换技能成为你应用这些技能到情景问题中的工具。

第三方对“Domain 1.1 = 将业务问题转化为Claude解决方案”的框架对于课程设计师来说很方便，但考试并不是这样评分的。考试是根据由转换技能驱动的架构决策来评分的，而不是将转换技能作为一个独立的技能来评分。

如果你正在备考CCA-F，我的建议是：

1. 从头到尾阅读官方考试指南PDF。它很短且直接。
2. 阅读Anthropic的“构建有效代理”工程博客。它定义了考试依赖的工作流与代理的区别。
3. 阅读平台文档，包括提示缓存、停止原因和代理SDK概览。
4. 在代码中实践七个Domain 1任务陈述。构建使用子代理、程序化执行和`stop_reason`控制的项目。
5. 如果有时间，可以将五支柱业务转换框架作为解释决策的备考辅助工具。

考试奖励那些能够思考架构的人，而不是那些能够背诵转换框架的人。先构建，后贴标签。
