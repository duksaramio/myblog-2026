## 会议室里的瓶颈可能就是空气 — 693票

**来源：** [blog.mikebowler.ca](https://blog.mikebowler.ca/2026/07/03/co2-and-decision-making/)

迈克·鲍勒随身携带一个便携式二氧化碳监测仪参加会议。他发现的结果令人担忧但也不足为奇：封闭的会议室内的二氧化碳浓度通常在1000到2500 ppm之间，劳伦斯·伯克利国家实验室的研究表明，在这些浓度下认知表现会显著下降。在2500 ppm时，九项决策指标中有七项落入研究人员称为“功能失调”的状态。

令人不安的暗示是：你最昂贵的人在做出最重要的决策时，是在一种会损害你所需认知功能的环境中进行的——策略、规划和压力下的信息处理。没有人注意到这一点，因为这种损害感觉就像正常的疲劳。人们会把这种“迷雾”归咎于会议时间过长或睡眠不好，而没有人想到去测量空气。在家中的小办公室里工作的远程工作者在门关着的情况下也会面临同样的物理问题。开窗吧，这可能是你做出的最便宜的生产力干预之一。

## 或许你应该学点东西 — 375票

**来源：** [marginalia.nu](https://www.marginalia.nu/log/a_135_learn/)

Marginalia搜索引擎的创建者发布了一篇直截了当的文章：如果你在播放Netflix的同时刷手机，你就有时间学习一些东西。可以是像素艺术、音乐、木工、一门语言——随便选一个。这篇文章的实际价值在于它诚实地管理了人们的期望：学习一开始会很艰难，每次会话结束时表现都会变差，而改进则发生在睡眠中，而不是实践中。大多数人会在它变得实际容易之前就放弃了。

这是一篇能登上HN首页的文章，因为它说出了每个人都知道但需要再次听到的话。大多数成年学习者都卡在了“中等水平的 logarithmic 平台”——足够好以至有用，但不够好以至令人满意。这篇文章没有假装有绕过它的捷径。没有捷径。

## Leanstral 1.5：为所有人提供充足证明 — 337票

**来源：** [mistral.ai](https://mistral.ai/news/leanstral-1-5/)

Mistral 发布了 Leanstral 1.5，这是一个专注于 Lean 4 中形式验证的6B参数开源模型（Apache-2.0）。主要成果包括：在 miniF2F 上饱和，解决了 587/672 PutnamBench 问题，并在 FATE-H 上达到 SOTA（87%），在 FATE-X 上达到 34%。更有趣的是，它在测试的 57 个仓库中发现了 5 个以前未知的错误。

该模型通过中期训练、监督微调和 CISPO 强化学习进行训练。值得注意的不仅仅是基准测试——Mistral 正在提供一个专门用于实际证明工程的工具，该工具免费提供在 Hugging Face 上，并附带免费 API。形式验证长期以来一直被认为是“几乎有用”的。一个实际找到真实代码中真实错误的 6B 模型是一个有意义的步骤，使其成为常规操作，而不是学术研究。

## 每美元的性能正在变得更快更便宜 — 334票

**来源：** [wafer.ai](https://www.wafer.ai/blog/glm52-amd)

Wafer.ai 报告称，GLM-5.2 在 AMD MI355X GPU 上的吞吐量为 2,626 tok/s/node（聚合吞吐量），单流为 213 tok/s，声称比 NVIDIA Blackwell 的成本低 2 倍以上。他们将基础 bf16 模型量化为 MXFP4，声称在 GPQA-Diamond、tau2 和 GSM8K 等基准测试中保持无损质量。

标题很吸引人，但细节也很重要。他们达到了 B200 性能的 80%，而 GPU 成本仅为 2.75 倍，这在单位成本上是一个不错的胜利。但“相当的硬件规格”并不意味着“相当的软件生态系统”——NVIDIA 的原生支持和成熟的 CUDA 堆栈仍然是一个真正的优势。Wafer 承认，对于前沿模型，AMD 推理“很少能开箱即用”，可能需要几周的工程工作。差距正在缩小，但“缩小”和“关闭”是不同的词。无论如何，随着推理需求超过 Blackwell 的供应，务实性会获胜：如果 AMD 可以以一半的成本为你提供工作负载，只需一些前期优化工作，从数学上讲，最终会促使你切换。

## YouTube 创作者的私人视频泄露 — 301票

**来源：** [javoriuski.com](https://javoriuski.com/post/youtube)

一名安全研究人员发现，YouTube Studio 的 AI 助手“Ask Studio”存在漏洞，可以被利用进行提示注入攻击。攻击链非常巧妙：在创作者的视频上留下一个精心制作的评论，创作者打开 YouTube Studio，点击建议的 AI 提示（由 YouTube 设计），AI 将执行注入的指令，就像它们是自己的输出一样。攻击者甚至可以在发布后编辑一个看起来正常的评论——YouTube 不会重新通知创作者。

谷歌将此报告视为“不是安全漏洞”，需要“社会工程”。研究人员有力地反驳了这一点：这不是社会工程，因为用户从未见过恶意评论。他们与 YouTube 自身的受信任 AI 助手进行交互。真正的问题是 YouTube 的 AI 读取未经过滤的用户生成内容（评论），并将其作为输入处理——这是一起典型的注入漏洞。谷歌拒绝将其归类为安全问题要么是对攻击面的误解，要么是故意选择不修复它。

## 通过 htop/top 在 Linux 中解释你能看到的一切 — 309票

**来源：** [peteris.rocks](https://peteris.rocks/blog/htop/)

这篇文章虽然是 2019 年的经典之作，但仍然经常重新出现，因为它填补了一个真正的空白。文章详细介绍了 htop 中的每一个字段——负载平均值、进程状态（R/S/D/Z/T）、内存指标（VIRT/RES/SHR）以及它们之间的关系。作者使用 strace 和源代码来跟踪每个字段的实际含义，而不是猜测。

最有用的澄清是：一台双核机器上的负载平均值 1.0 并不意味着 CPU 使用率为 50%。负载平均值计算的是等待或使用 CPU 的进程（有时还包括 I/O），而不是 CPU 利用率百分比。这些是根本不同的测量值。如果你曾经盯着 htop 窗口，想知道为什么你的系统感觉很慢，尽管 CPU 数字很低，这篇文章会解释为什么。

## Workspace 实例之间可能存在会话/缓存泄漏 — 235票

**来源：** [github.com/anthropics](https://github.com/anthropics/claude-code/issues/74066)

Anthropic 的 claude-code 代码库中的一个 GitHub 问题报告了一个潜在的安全漏洞，即会话或缓存数据可能在不同的 workspace 实例或消费者账户之间泄漏。该代码库拥有 136k 星和 21.9k 个 fork，庞大的用户基础使得不同租户之间的理论数据泄漏成为一个严重的关切点。该问题仍然处于开放状态并正在调查中。

这种漏洞让平台工程师夜不能寐——缺乏租户隔离的共享基础设施。这是否最终成为真正的攻击手段或仅仅是理论上的担忧，取决于实现细节，但 235 点的高票数表明 HN 社区对此非常重视。对于任何在生产环境中运行 claude-code 或在共享机器上运行的人来说，值得密切关注。

## 线索

今天首页的两个主题占据了主导地位。首先，**直到失败才显现的基础设施**：会议室内的二氧化碳悄悄损害你的最佳决策能力，YouTube 的 AI 无声地执行来自评论的攻击指令，Claude Code 的缓存无声地在用户之间泄漏。共同之处在于，最危险的错误不是那些导致崩溃的错误——而是那些悄悄破坏你结果的错误。

其次，**AI 推理的经济正在快速变化**。AMD 的 MI355X 以一半的 Blackwell 成本提供服务，Mistral 发布了一个 6B 参数的开源模型，能够找到真实错误，Wafer 证明你可以用非 NVIDIA 硬件来提供前沿模型——所有这些都指向一个世界，在这个世界里，围绕 NVIDIA 价格优势的护城河正在侵蚀，即使软件生态系统之间的差距尚未完全关闭。AI 硬件市场开始看起来更像是一个真正的市场，而不是一个垄断市场。
